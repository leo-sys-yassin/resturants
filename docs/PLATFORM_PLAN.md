# خطة منصة المنيو للمطاعم

الحالة: خطة للعمل لاحقاً. لا تنشئ هذه الخطة أي خدمة أو اشتراك أو ربط مع أنظمة مطعم.

## حدود المنتج

المنيو مستقل عن خادم المطعم وقاعدة بياناته والكاشير والمطبخ والمحاسبة. لا نحتاج بيانات دخول أو وصولاً إلى تلك الأنظمة. قاعدة بيانات منصتنا تحفظ إعدادات المنيو والأصناف والأسعار والمكونات وحسابات الإدارة فقط. لا تشمل المرحلة الأولى طلبات أو مدفوعات أو مخزوناً. أي تكامل لاحق يُنفذ باتفاق منفصل عبر API مناسب.

## المنصة المشتركة

منصة واحدة تدعم عدة مطاعم وقوالب: وجبات سريعة، سوشي، كافيهات، ومندي. لكل مطعم معرّف ثابت ورابط QR ثابت وحسابات إدارة وبيانات وصور وقالب مستقل. تبقى بيانات المطاعم معزولة بصلاحيات تُفحص في الخادم وقاعدة البيانات.

## توزيع الخدمات

- Cloudflare Pages: واجهة المنيو ولوحة الإدارة المتجاوبة للجوال والتابلت والكمبيوتر.
- Supabase: تسجيل دخول الإدارة، العضويات والصلاحيات، إعدادات المطعم، المسودات والأصناف والأسعار وسعر الصرف.
- Cloudflare R2: صور محسّنة ونسخ المنيو المنشورة للعامة.
- Cloudflare Worker: نقاط إدارة الرفع والنشر؛ يتحقق من التوكن وعضوية المطعم قبل أي تعديل على التخزين.

تُستخدم خدمات مستقلة عن مشاريع REX. لا تُوضع مفاتيح الإدارة أو تخزين R2 داخل كود الزبائن، ولا يُعتبر رابط لوحة الإدارة حماية بحد ذاته.

## طريق الزبون

QR ثابت → واجهة المنيو → نسخة منشورة من R2 عبر الكاش. لا تسجيل دخول للزبون ولا استعلام مباشر إلى Supabase لكل زيارة. لا اتصال تلقائي بأنظمة المطعم أو طلباته.

## طريق الإدارة والنشر

تسجيل دخول → تعديل مسودة → معاينة → نشر.

تُرفع الصور بأسماء جديدة، وتُنشأ نسخة JSON كاملة برقم إصدار. بعد نجاح التحقق ورفع الملفات، يُحدّث مؤشر النسخة النشطة أخيراً. فشل النشر يُبقي النسخة السابقة صالحة. نحتفظ بإصدار سابق للرجوع إليه. نبدأ بكاش قصير لمؤشر الإصدار، نحو 60 ثانية، وكاش طويل للصور والملفات ذات الإصدارات؛ لا نبقي اتصال مزامنة مفتوحاً لكل زبون.

## إدارة المحتوى

اسم المطعم وهويته وتواصله وساعات عمله؛ الأقسام وترتيبها؛ الأطباق وتوفرها وصورها؛ أسماء وأوصاف ومكونات وحساسية بالعربية والإنجليزية؛ سعر أساسي بالدولار أو الليرة وسعر صرف يحدده المطعم؛ أسعار الإضافات؛ تصدير ونسخ احتياطي واسترجاع.

## مراحل التنفيذ

1. تثبيت تجربة المنيو والإدارة المحلية الحالية وتجربة القوالب والأجهزة.
2. اختيار مشروع مستقل للمنصة وحسابات الخدمة، ومراجعة شروط التفعيل والتكاليف قبل إنشاء الموارد.
3. بناء حسابات الإدارة وعزل المطاعم وصلاحيات البيانات والرفع.
4. ربط المسودات والصور والنشر ذي الإصدارات والكاش والرجوع لإصدار سابق.
5. فحص الصلاحيات، ومنع وصول مطعم لبيانات مطعم آخر، وفشل النشر، والاسترجاع، وأداء الجوال والتابلت والكمبيوتر.
6. اختبار تحميل للنسخة المنشورة وقياس أحجام الصفحات وطلبات التخزين والنقل والذروة.
7. تجربة تشغيل محدودة قبل البيع، ثم تحديد الباقات والعقد والدعم وحدود الاستخدام.

## ميزانية المجاني وقياس القدرة

الهدف التخطيطي السابق 5–10 مطاعم بحدود 15 ألف زيارة شهرياً لكل مطعم ليس ضمان سعة. نحدد القدرة بعد النشر والقياس، مع احتساب كل حصص الخدمات المشتركة والطلبات الإضافية. نراقب تخزين الصور وعمليات القراءة والكتابة ونقل البيانات والمعالجة والمصادقة. النسخة المحلية الحالية لا تمثل بعد نظام حسابات أو مزامنة إنتاجياً.

## ما يحتاج قراراً لاحقاً

اختيار مؤسسة ومشروع Supabase مستقلين، تفعيل خدمات Cloudflare اللازمة، نطاق المنصة، وسائل بريد الإدارة واستعادة الدخول، وشروط الصيانة. لا يلزم أي وصول إلى سيرفر المطعم.
